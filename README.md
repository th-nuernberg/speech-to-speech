# Pitch playground — UNO Q hackathon starter

Give your voice a lift: record a phrase, turn a Modulino Knob, hear it at a higher pitch.
The STM32 shows the selected pitch on the UNO Q LED matrix. Python on the Q's Linux
processor handles audio. No speech model or downloaded voice is required.

The organizer has tested recording, shifted playback, knob control and the LED marker
on the physical UNO Q. It processes
short recordings, not continuous live audio. Pitch is sampled before each playback;
turning the knob during playback changes the next playback. The LEDs show the selected
shift, not the measured pitch of your voice. +12 semitones doubles frequency while
keeping the recording length. Some voice artifacts are expected.

## Hardware

- Arduino UNO Q (your setup: 4 GB), powered USB-C hub and USB audio adapter/microphone.
- Modulino Knob connected by Qwiic to the Q. It is a rotary encoder, not an analog pot:
  use its cable, with no analog or 5 V wiring. Power down before connecting modules.
- Headphones for first tests; select the microphone and playback device in Linux.
- Your Elecrow 1024×600 HDMI/USB touchscreen is optional for this terminal demo.
  It can show App Lab and logs. Display audio needs a separately verified route.

```text
Modulino Knob → STM32 → onboard 8×13 LED matrix
                  ↕ Bridge RPC: pitch_semitones
USB microphone → Linux/Python → pitch shift → USB audio/headphones
```

## 1. Try audio on your laptop first

Use Python 3.11/3.12. On Debian/UNO Q the host audio path needs PortAudio
(`libportaudio2`); a plain virtual environment also needs `python3-venv`.

```sh
python3 -m venv .venv-pitch
source .venv-pitch/bin/activate
python -m pip install -r pitch_demo/python/requirements.txt
python pitch_demo/python/pitch.py --list-devices
python pitch_demo/python/pitch.py --semitones 6
```

Enter `r` to record three seconds, `o` to hear the original, `p` to hear the shift,
`k` to inspect the setting, and `q` to quit. Without Bridge, `--semitones` sets pitch.
Use `--input-device N --output-device N` to select device IDs from the device list.
`--seconds 5` changes recording length. Start at low headphone volume.
The first pitch shift can be slow because numerical code initializes/compiles.
Both demos keep recorded audio in memory and play it through the selected audio
output. They do not save WAV files.

## 2. Run the knob and matrix on the UNO Q

1. In Arduino App Lab create a new empty app. Keep the metadata generated by your
   installed App Lab version.
2. Replace its sketch with `pitch_demo/sketch/sketch.ino`.
3. Add **Arduino_Modulino** with its dependencies via the app's library management.
   `Arduino_LED_Matrix` comes from the UNO Q Zephyr core; use the Q version.
   The sketch also uses `Arduino_RouterBridge` supplied by the Q environment.
   On current platforms it is bundled; do not add it as an explicit library dependency.
4. Copy both `pitch_demo/python/main.py` and `pitch_demo/python/pitch.py` into
   the app's `python/` directory. Copy `requirements.txt` there too.
5. Enable microphone and speaker/audio device access in App Lab if required by
   your version. First try an included audio example to confirm container access.
6. Run the app. Watch the logs: it records 3 seconds, reads the knob, processes,
   plays the result, waits 2 seconds, and repeats. Stop it with App Lab's Stop button.

Turn the knob clockwise: 0 → +12 semitones. Counterclockwise lowers the setting.
The two-pixel vertical marker moves from bottom to top in seven visual positions.
Each encoder count changes pitch by one semitone; several settings share a position.
A diagonal at startup means the knob was not found: check the cable and restart.

The automatic App Lab loop needs no terminal input. It uses default audio devices.
For alternate devices, adapt `device=` in its `sd.rec` and `sd.play` calls after
listing devices in that same runtime. A desktop virtual environment and an App Lab
container can see different devices. System PortAudio support must exist inside
that runtime as well; installing it only on the host may not be sufficient.

Advanced: `pitch.py --bridge` provides the interactive terminal version in a Q Python
environment that already supplies `arduino.app_utils` and router connectivity. A
normal laptop pip environment does not include the Q Bridge runtime.

## First attendee challenges

1. Compare 0, +6, +12 semitones on the same phrase. What changes besides pitch?
2. Replace the marker with a rising bar or a scrolling numeric value.
3. Add a bypass/record action using the knob's push button.
4. Extend the range to negative shifts (update both sketch and Python validation).
5. Measure processing latency, then explore a streaming pitch shifter with smoothing.

## Troubleshooting and validation

- No recording/playback: check the device list and test USB audio independently.
- Bridge method missing: ensure both app halves run, the sketch has uploaded, and
  no other app owns the Bridge method. Match the name `pitch_semitones` exactly.
- LED orientation differs on your bench: adapt `showPitch()` row mapping.
- Knob does nothing: use Qwiic/Wire1 and Arduino_Modulino's Knob example first.
- Installation fails on ARM64: validate wheels/system dependencies on the Q before
  the event. Version ranges are not a board-tested lockfile.
- Feedback: use headphones and keep the microphone away from the output speaker.

Local processing check (no microphone or board required):

```sh
python -m unittest discover -s tests -v
```

Before the event: compile/upload the sketch; test both endpoint positions, knob
recovery, recording and replay; time the first and subsequent pitch shifts; freeze
the working dependencies in the board's Python environment.
Repeat these checks for each attendee setup. The organizer's end-to-end UNO Q audio,
knob and LED test succeeded. Confirm you are listening to the headphones actually
connected to the UNO Q USB audio adapter.

## Repository files

- `pitch_demo/sketch/sketch.ino`: Qwiic encoder, LED marker, Bridge getter.
- `pitch_demo/python/main.py`: automatic App Lab recording/playback loop.
- `pitch_demo/python/pitch.py`: audio processing and standalone terminal demo.
- `pitch_demo/python/requirements.txt`: pitch demo dependencies.
- `tests/test_pitch.py`: audio processing checks that run without the board.
